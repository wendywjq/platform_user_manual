说明：决策

一、背景

Zeus普通场景 或 分层场景-策略节点中部署策略时，需要对规则配置一个决策，决策在执行规则命中后会输出给调用方。

对于Tatooine事件接入的流量，Zeus返回的决策会在Tatooine中统一翻译为风险等级（risklevel）向下游进行输出。学城文档 1358367295（无权限读取标题）

目前，Zeus决策根据特点和属性，被分为三个类型：普通决策、异步决策、组合决策。

二、名词解释

名词

解释

决策 (decision)

命中规则后需要做的动作，每一条scene_rule_conf配置产生一个决策；针对结果的处理动作，例如：通过、拦截、冻结账号、加入黑名单等；

决策合并

Tatooine事件接入的流量，在规则执行命中的决策后，将会按照一定逻辑进行合并后再输出。

目前普通场景、路由场景 自身没有决策合并能力，会统一在Tatooine进行合并。

分层场景本身具备决策加工组件，对场景内的合并都会完成后再输出给Tatooine，若涉及场景间汇总才会在Tatooine进行。

普通决策

普通决策参与决策合并（分层场景-决策加工 或 Tatooine决策合并），在分层场景「补偿链路」中命中时无法输出；

例如：通过、拦截、各种验证方式

异步决策

异步决策不参与决策合并，在分层场景的实时和补偿链路，只要命中都会输出给Tatooine执行（不输出下游）。

由于其异步执行的特点，也可用作分层场景-补偿链路中，作为普通决策的「补偿决策」进行配置。配置方法见：决策加工组件

例如：写kv、写名单、加入persona等

组合决策

仅支持在分层场景中使用。组合决策是一串由【且、或】逻辑拼接的普通决策ID，内部可进一步细分多个顺位。

在3-账户安全空间中，分层场景默认的决策加工方式是输出【组合】的模式（非单个决策），因此执行上会先将组合决策拆为多个单决策，经过Yoda过滤后，再作为整体（一个优先级）参与决策合并。

例如：【三方验证，支付密码验证|人脸验证,客服验证】

决策优先级

仅作为【分层场景】中的决策加工组件的决策合并依据，数字越小意味着优先级越高。不影响普通/路由场景中的执行。存量决策（未配置优先级）默认置为最低值9999。

决策附加信息

规则命中时，随决策一起输出的key-value型结构化数据，包含常量和动态的变量。在决策所指定的附加信息模板中填充具体的数据后就是一条附加信息，一个附加信息只属于一个决策。说明：Zeus决策附加信息使用文档

决策理由

描述决策的具体细节，比如当决策是拦截时，其可能的原因包括拒绝快捷支付、拒绝绑卡等，决策理由指定了做出决策的具体原因。

一般下游业务将此字段用于C端文案透出。在场景配置策略时，决策理由和决策是分别独立的字段，没有互相依赖关系。

三、操作说明

3.1 决策管理

说明

图例

【决策管理】

入口：菜单-策略部署-决策

搜索查询：

  • 可根据多条件自由进行决策的检索。

列表：

  • 在列表中可获取到决策的基本信息如：ID、名称、类型、映射risklevel、优先级、有无使用附加信息、在场景中的应用情况等。
  • 点击名称，进入决策详情预览。
  • 名称下方展示的红标签为场景专用，代表该决策仅能被这些场景引用。
  • 映射risklevel：展示决策在Tatooine对应的risklevel值，如果是组合决策，会分行来展示不同顺位的risklevel。
  • 点击场景中的应用次数，可查看决策的引用明细

3.2 新建/编辑决策

说明

图例

【新建/编辑决策】

点击右上角【新建决策】按钮，进入新建页，填写后点击提交。

  • 决策名称：自定义
  • 决策类型：默认普通决策，根据需要选择需创建的类型。

新建的「异步决策」需要在Tatooine开发对应后置能力，才可投入使用。否则，输出到Tatooine后并不会执行相关动作。

根据特点，异步决策也不会像普通决策那样参与决策合并。

如有新增异步决策需求--可联系Tatooine产研@张锡川

  • 决策优先级：支持输入范围为1-9999，历史存量决策默认值为最低优先级9999，数字越小意味着优先级越高，建议百级加减预留空位。决策在其他空间共享时，优先级不会共享与联动，需要分别设定。
  • 附加信息：默认不使用，可选择使用，右上角按钮变为「下一步」，方可进一步配置。说明：Zeus决策附加信息使用文档
  • 设置专用场景：目前仅对3空间开放。配置后，其他非此处列举的场景，不可引用此决策。

如其他空间有需要，可联系产研也开放此功能。

  • 标签：与规则、场景类似，决策也支持打上管理类标签，便于用户进行管理和维护。

3.3 组合决策

说明

图例

【组合决策】

组合决策是一串由【且、或】逻辑拼接的普通决策ID，内部可进一步细分多个顺位。组合决策在配置上比其他决策多一个部分「组合配置」

默认可输入第一顺位的组合，也可以点击 [+] 向下增设多个顺位组合，用于替补上一级组合被完全过滤至空的情况。

每个顺位中，支持以英文','和'|'来输入'且'和'或'逻辑拼接而成的决策ID串。

Q：为什么需要使用组合决策？

A：下图中4条规则配置，使用的是同一条规则（本质是同一条规则id，这里是配置有误，用了4条，可忽略），来源于同一个风险判断逻辑，但是希望出决策的时候，各个组合决策之间有一个优先排序。比如：最高优出【短信 / 支付】，如果被Yoda可验证过滤后空，则其次期望出【短信/人脸/客服】， 然后是【短信】 最后才是【客服】。——组合决策可以实现这种多个单决策的拼接输出，以及多个顺位间 输出的顺序关系。

Q：怎么理解顺位的作用？

A：如右图，说明了组合决策参与决策合并的执行逻辑。
决策默认被翻译为顺位1 ，但是如果顺位1被Yoda可验证过滤完变空，而顺位2 没有过滤完，则取顺位2的结果作为组合决策实际输出的内容。优先级依旧是整个组合决策设定的100，然后参加下一步的决策合并。

Q：什么是Yoda可验证过滤，我的场景在决策加工时有这个步骤么？

A：目前仅开放给3空间的分层场景，用于账户安全在输出各种验证方式后，统一在yoda进行过滤，排除掉当前设备/用户不支持的验证决策。

Q：组合决策需要配置risklevel的映射么？

A：不需要（也无法配置）。组合决策由「普通决策」拼接而成，仅需要保证用到的「普通决策」有映射risklevel即可。

3.4 预览决策详情

说明

图例

【预览决策详情】

点击决策名称，打开详情页。

展示内容即为编辑提交的信息，其中有字段【risklevel】展示的是当前决策在Tatooine中配置的映射risklevel。

可点击后方【配置risklevel】，打开Tatooine平台-风险等级 管理页，进行risklevel映射的配置。

组合决策的【risklevel】会分多个顺位，分别展示组合决策串映射而成的risklevel串。

当不存在映射值时，展示为“-”

组合决策整体不允许单独在Tatooine中映射risklevel

3.5 内容安全加工决策

仅对于35空间 206-UGC图片疑似、205-UGC图片删除、187-UGC删除、173-UGC疑似 四个决策支持下述能力

说明

使用方式：当决策下附加信息中某一字段key的加工方式为明细加工输出时，若命中该决策，对应的字段key将带上对应的规则风险标签输送至保时洁。

step1-了解决策中的附加信息字段含义

决策下默认已配置好四个明细加工输出类模版key字段，分别代表保时洁所接收的图/文/动图/视频list字段

step2-新增附加信息

点击下方附加信息右侧「添加信息」按钮，进入附加信息添加弹窗中。

  1. 对于上述四个明细加工输出类模版key，在对应的key后方填写业务原始入参。
  2. 填写后，若命中当前决策，则规则风险标签携带入右侧所填写的原始命中索引入参中送向对应保时洁所接收的字段。

  3. 具体命中索引会根据条件间逻辑取交并集，可能存在交集为空情况，可在弹窗末尾配置对于此类情况的兜底打标方式。

    携带方式数据结构 
    "contentTextList" : {0:[{ // 文字执行结果
      "ruleId": 123,     // 规则ID
      "decisionId": 188, // 决策ID
      "tagCode":[111],   // V3标签Code
      "extraInfo": {     // 附加信息，机审固定的附加信息输出字段如下
        "remarks": "",
        "DPVerifyStatus": 0,
        "DPVerifyTips": "",
        "operation": "pass",
        "HLVerifyStatus": 0,
        "HLVerifyTips": ""
      }
  }]}

step3-将附加信息配置到对应的场景配置中

在识别树中选择对应的决策及附加信息，命中对应配置后即执行对应的附加信息加工
