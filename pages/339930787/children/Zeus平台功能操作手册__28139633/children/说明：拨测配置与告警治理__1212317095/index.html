说明：拨测配置与告警治理

一、背景

Zeus平台的近线引擎稳定性和可用性直接影响公司入侵发现及时性和有效性。

但从已迁移作业-故障汇总可知作业异常case频发，6月至今（07-06）共 11 起异常case，其中 2 起事故直接导致漏报，因此迫切需要正向建设Zeus作业稳定性、及告警有效性。

拨测直接向近线引擎输入kafka写入数据。在生产环境进行实际数据处理（但是不会触发真实报警）。命中规则结果会进行统计。用于长期监测规则的有效性。

由于拨测为近线引擎（基础安全方向）个性化功能，因此只在130-反入侵下展示，其他业务方需要使用的话需要先联系PM@丁婷婷和RD@高大亮

二、名词解释

拨测：用户自定义流量调用场景规则获取决策，判断结果是否满足用户诉求的任务配置

三、操作指南

1.用户操作流程说明

  1. 拨测配置

    说明

    页面

    【入口】

    1. Zeus-->策略排查-->拨测设置

    2. Zeus-->规则-->规则详情-->拨测配置

    【配置-单条配置1】

    从规则详情页跳转配置（从规则详情页跳转拨测配置只能针对单条规则配置）

    1. 点击规则详情页右上角的「拨测配置」按钮，跳转拨测配置详情页；

    2. 基本信息模块：

      1. 拨测规则：系统自动带出需要配置拨测的「规则ID-名称」，可修改调整切换成其他规则，必填；一旦选择，不能修改。
      2. 拨测场景：需要用户下拉选择，即确定此次配置的拨测任务是要过哪个场景，下拉选项为该规则在该业务空间下添加的所有场景，必填；一旦选择，不能修改。
      3. 产品线：下拉选项，用户自行选择，选项内容含：webids、hids、rasp、nids、edr、sysmon、dns、dbaudit、蜜罐；必填；产品线用于统计拨测的准确率的BI大盘和报表分析。一旦选择，不能修改。
      4. 拨测类型：下拉选项，可选 全链路、半链路。
      5. 任务名称：当用户选中规则、场景、产品线后，系统会自动拼接任务名称并展示，拼接逻辑为「autotest_产品线_场景id_规则中文名」，支持用户在此基础上进行修改任务名称，（备注：但是用户如果修改过一次任务名称后，重新选择产品线或者拨测场景或拨测规则，任务名称不会随之拼接，需要用户手工修改。）必填；
      6. 任务状态：running/debug 二选一，系统默认running，必填；用户选择debug状态，则数据不会进行报表统计。建议新建拨测使用debug状态。
      7. 超时判断：支持用户输入超时时间标准，支持秒/分/时三个级别的，必填；
      8. 告警配置：支持用户设定任务告警阈值，基准为拨测任务近24小时的拨测成功率，用户可以定义任务成功率在什么区间进行告警，非必填；填写内容如<0.9，表示拨测成功率小于90%则进行报警。
      9. 告警接收人：接收大象告警通知的用户，直接填misid，可以填多个，非必填；填写多个是请用英文逗号分割。

    3. 逻辑配置模块：

      当选择半链路拨测时：

      1. Kafka：下拉选择kafka topic，先输入再点选，下拉选项为有权限的topic，如果发现下拉选项里没有想要的topic，需要在zeus平台上注册该数据源；必填。而且需要申请mt-ids-zeus项目组对该数据源的写入权限。如何申请请参考FAQ。
      2. 数据类型：单选，选项为new log、log、snappy，必填，选择数据类型后，系统会自动将content部分转成所选的数据类型，必填
      3. content：用户填写topic内容，必填。无论用户选择什么数据格式，都请填写JSON数据格式。系统会自动进行转换后进行发送。

      当选择全链路拨测时：

      1. 主机名：下拉选择主机名
      2. 数据类型：默认命令
      3. content：用户填写内容，必填。
    4. 操作：支持添加数据和删除数据
    5. 注意：如果一个拨测任务下如果配置了多个数据源，表明这个拨测需要几个数据源同时操才能触发，此时，这些数据源会同步发送。需用户注意

    【配置-单条配置2】

    从拨测配置tab跳转配置

    1. 点击右上角「拨测配置」按钮，跳转拨测配置页面
    2. 拨测配置页面内容同【配置-单条配置1】，只是该页面不会自动带出规则信息，需要用户手工输入，其余配置一致；
    3. 同样区分半链路拨测和全链路拨测

    【配置-批量配置】

    从拨测配置tab跳转配置（批量拨测配置支持对同一个场景下的规则）

    1. 点击右上角「批量拨测配置」按钮，跳转批量配置页面

    2. 基本信息模块：

      1. 拨测场景：先key字段，支持模糊匹配该businessid下的场景，可以对一个场景下的多条规则同时配置拨测，必填；
      2. 产品线：即确认需要批量配置的是哪个产品线，一次批量配置只能配置一个产品线的，产品线下拉选项，用户自行选择，选项内容含：webids、hids、rasp、nids、edr、sysmon、dns、dbaudit、蜜罐；必填；
      3. 任务状态：running/debug 二选一，系统默认running，必填；
      4. 超时判断：支持用户输入超时时间标准，支持秒/分/时三个级别的，必填；
      5. 告警配置：支持用户设定任务告警阈值，基准为拨测任务近24小时的拨测成功率，用户可以定义任务成功率在什么区间进行告警，非必填；
      6. 告警接收人：接收大象告警通知的用户，直接填misid，可以填多个，非必填；

    3. 逻辑配置：

      1. 规则：可下拉选择所选场景下的规则，一行只能选择一条规则，选定规则后，会自动带出该规则在指定场景的状态；
      2. 任务名称：当用户选中规则、场景、产品线后，系统会自动拼接任务名称并展示，拼接逻辑为「autotest_产品线_场景id_规则中文名」，支持用户在此基础上进行修改任务名称，（备注：但是用户如果修改过一次任务名称后，重新选择产品线或者拨测场景或拨测规则，任务名称不会随之拼接，需要用户手工修改。）必填；
      3. Kafka：下拉选择kafka topic，先输入再点选，下拉选项为有权限的topic，如果发现下拉选项里没有想要的topic，需要先申请权限；必填
      4. 数据类型：单选，选项为new log、log、snappy，必填，选择数据类型后，系统会自动将content部分转成所选的数据类型，必填
      5. content：用户填写topic内容，必填

      6. 操作：支持添加数据和删除数据

        注意：

        1. 批量配置拨测任务页面，支持对一条规则配置多个数据源，也支持多条规则配置不同的数据源。
        2. 批量拨测配置时，任务生成维度为规则，如果逻辑配置模块，选了N条不一样的规则，最终生成的任务为N个任务，如果对1条规则配置了M行数据配置，最终生成的任务为1个

    【修改/删除】仅支持任务维度修改/删除

    1. 点击进入拨测配置tab，点击列表项的「任务名称」，直接跳转到指定任务详情页；

    2. 点击任务详情页的「编辑」按钮，跳转至拨测任务修改页面，仅支持修改任务状态、超时判断、告警配置、告警接收人、拨测逻辑配置模块。

    【修改任务状态】

    在任务列表页可以快速修改任务状态

    1. 点击操作列的「编辑」按钮，可以直接修改任务状态，选定后点击保存则状态切换成功；
    2. 只有状态=down的任务可以删除，其余不可删除

    【拨测任务成功率查看】

    1. 拨测状态：一条规则可以配置多个拨测，在规则场景页面（即规则维度），展示的拨测状态为这条规则配置的所有拨测任务的汇总状态，共计四个状态，优先级：Running > Debug > Down > None

      1. None：表示该规则没有配置任何一条任务；
      2. Down：表示该规则配置过拨测任务但当前所有任务均为Down状态；
      3. Debug：表示该规则配置过拨测任务但当前任务状态没有Running状态的；
      4. Running：表示该规则配置过拨测任务且当前任务状态有Running状态的；
      5. 任务维度则展示该任务的状态，只有Running 、Debug、 Down

    2. 拨测成功率：计算公式为：RUNNING 拨测用例成功数 / RUNNING 拨测用例总数

      1. 规则维度：成功率=该规则在该场景下统计时点所有状态=running的任务过去24h的sucess的用例数/该规则在该场景下统计时点所有状态=running的任务24h的用例数
      2. 任务维度：成功率=统计时点状态=running的任务过去24h的sucess的用例数/统计时点状态=running的任务24h的用例数

  2. 告警治理（主要为运维，非配置页）

说明

页面

【入口】

  1. Zeus-->策略排查-->告警治理

【操作】

  1. 待治理：

    1. 待治理查询区可以通过筛选指标分类和指标名称，精准定位所需要治理的告警
    2. 治理：可以通过点击操作列的治理按钮，进行治理+填写告警原因，便于后续分析，也可以通过将鼠标hover告警内容上，悬浮展示具体告警内容，并在快速解决模块点击操作项，即可对告警进行治理

  1. 已治理：

    1. 所有已治理的告警均会从未治理转到已治理模块；
    2. 已治理的查询区比未治理多了「处理方式」和「misid」

    3. 列表项比未治理多了告警原因、处理方式、告警跟进人和跟进事件、时效

      1. 告警原因为用户在告警治理时所填写的告警原因，如果用户选择快速解决，则无告警原因
      2. 处理方式为用户在告警治理时所选择的处理方式
      3. 告警跟进人为进行告警治理的用户的misid和进行告警治理的时间
      4. 时效：为告警报出到被治理的时间，精确到小时，四舍五入计算


2.特殊说明

拨测中涉及可变时间的情况：

部分拨测需要传入的数据中要求时间可变（比如说规则中有自动过滤过期数据的逻辑）。此时，需要使用另外的格式。

内容中支持的时间格式为

#DIAL#{时间格式 MINUS 时间段}#DIAL#

简单例子如下

#DIAL#{yyyy-MM-dd HH:mm:ss MINUS 1d}#DIAL#

注意，时间段目前只支持m(分钟) h(小时) d(天)

时间格式可以填写java joda支持的时间格式。
